DEPLOYMENT

انتشار روی هاست استاتیک

برای اجرای نسخهٔ فعلی، Node.js یا build اجباری نیست؛ وب‌سرور باید فایل‌ها را با ساختار نسبی حفظ کند.

OPTION A

هاست معمولی یا cPanel

  1. محتویات مخزن را دریافت کن.
  2. فایل‌های سایت را در public_html آپلود کن؛ پوشهٔ .git لازم نیست.
  3. ساختار پوشه‌های assets، data و docs را حفظ کن.
  4. برای نصب‌پذیری و Service Worker گواهی HTTPS فعال باشد.
  5. صفحه را روی موبایل و دسکتاپ آزمایش کن.
OPTION B

GitHub Pages

  1. به Settings → Pages در مخزن برو.
  2. Source را روی GitHub Actions بگذار.
  3. Workflow موجود در .github/workflows/pages.yml با هر push روی main اجرا می‌شود.
  4. وضعیت اجرای Workflow و URL انتشار را در Actions بررسی کن.
  5. برای دامنهٔ سفارشی، DNS و HTTPS را نیز تنظیم کن.

تنظیم Source روی GitHub Actions در تنظیمات Pages لازم است؛ فایل Workflow به‌تنهایی تضمین نمی‌کند سایت منتشر شده باشد.

نکتهٔ مهم دربارهٔ «سرویس دادن»: نسخهٔ فعلی یک وب‌اپ استاتیک مناسب نمایش عمومی پلن‌هاست، اما سیستم اشتراک امن چندکاربره نیست. ورود کاربر، پرداخت، محدودیت دسترسی سمت سرور، پنل مدیریت، API قیمت زنده و ذخیره‌سازی ابری در این نسخه وجود ندارند. هیچ محتوای محرمانه یا پلن ویژهٔ مشترکین را داخل فایل‌های عمومی قرار نده.

BOUNDARIES & SAFETY

حدود نسخهٔ فعلی

PLAN ابزار تحقیق و برنامه‌ریزی است؛ توصیهٔ شخصی سرمایه‌گذاری، کارگزار یا موتور ارسال سفارش نیست.

این نسخه Backend ندارد. داده‌های پلن در فایل JavaScript عمومی قرار دارند و برای هر بازدیدکننده قابل دریافت‌اند. کلیدهای API خصوصی، رمز عبور یا پلن محدود به اشتراک نباید در فایل‌های عمومی قرار بگیرند.

قبل از ارائهٔ نسخهٔ پولی به کاربران، باید احراز هویت سمت سرور، مجوز دسترسی، مدیریت مشترکین و پرداخت، سیاست حریم خصوصی، شرایط استفاده، پشتیبان‌گیری و مانیتورینگ جداگانه طراحی و پیاده‌سازی شوند.
