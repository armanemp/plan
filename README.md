# PLAN — Trading Desk / Daily Market Journal

میز تحلیل استاتیک، فارسی و راست‌چین برای پلن‌های روزانه. این پروژه عمداً بدون API، وابستگی خارجی یا دادهٔ ساختگی کار می‌کند. چارت با Canvas داخلی رسم می‌شود و فقط کندل‌ها، سطوح و ناحیه‌هایی را نشان می‌دهد که در رکورد همان پلن ثبت شده‌اند.

## وضعیت طراحی

- چارت‌محور: چارت، نماد، تایم‌فریم و برداشت روز در مرکز تجربه هستند.
- بدون قیمت ساختگی: تا وقتی OHLC تأییدشده وارد نشود، چارت خالی و واضح باقی می‌ماند.
- روزانه قابل توسعه: هر تاریخ یک رکورد جدید در آرایهٔ plans است؛ رکورد قبلی حذف یا جایگزین نمی‌شود.
- قابل اجرا آفلاین: HTML/CSS/JS ساده، بدون CDN و فونت آنلاین.
- اعتبارسنجی خودکار: اسکریپت Node ساختار تاریخ‌ها، سناریوها و OHLC را کنترل می‌کند.
- دسترس‌پذیر و responsive: صفحه‌کلید، فوکوس قابل مشاهده، حالت موبایل و چاپ/PDF.

## شروع

1. پروژه را با Git کلون کن.
2. برای اجرای بدون وابستگی، فایل index.html را باز کن. برای اجرای آزمون‌ها Node.js نسخهٔ 20 یا بالاتر لازم است.
3. استاندارد کامل داده و یک الگوی رکورد در docs/DAILY-PLAN-SPEC.md قرار دارد.
4. هر روز فقط یک شیء تازه به ابتدای آرایهٔ plans در data/plans.js اضافه کن.
5. ابتدا status را draft نگه دار. پس از بازبینی قیمت، زمان، منابع، خبرها، سناریوها و ریسک، وضعیت را به ready تغییر بده.
6. اعتبارسنجی را اجرا کن: node scripts/validate-plans.mjs
7. پس از بررسی ظاهر دسکتاپ و موبایل، تغییر را commit کن. روزهای گذشته را بازنویسی نکن؛ اصلاحیه را در notes ثبت کن.

## ساختار پروژه

- index.html — ساختار رابط کاربری
- assets/css/app.css — طراحی، responsive و چاپ
- assets/js/app.js — رندر، کنترل تعاملات، رسم چارت و اعتبارسنجی سمت مرورگر
- data/plans.js — تنها محل ثبت داده‌های روزانه
- scripts/validate-plans.mjs — کنترل خودکار قرارداد داده
- docs/DAILY-PLAN-SPEC.md — قرارداد و نمونهٔ کامل
- docs/DAILY-WORKFLOW.md — گردش کار روزانه
- .github/workflows/quality.yml — کنترل کیفیت هنگام push و pull request

## قراردادهای مهم

- همهٔ زمان‌ها به وقت Asia/Baku ثبت شوند و زمان/منبع قیمت مرجع مشخص باشد.
- کندل‌ها باید OHLC واقعی و زمان مرتب داشته باشند؛ هیچ نمونهٔ نمایشی یا عدد ساختگی برای پر کردن چارت اضافه نکن.
- هر سناریو باید شرط فعال‌سازی و ابطال داشته باشد. وضعیت ready به معنی تکمیل فرایند بازبینی است، نه تضمین نتیجه.
- این سایت دادهٔ زنده دریافت نمی‌کند و سفارش ارسال نمی‌کند. اطلاعات قبل از تصمیم باید از منبع اصلی دوباره بررسی شود.
- اگر داده‌ای موجود نیست، مقدار را نامشخص بگذار؛ آن را حدس نزن.

## انتشار

برای انتشار در GitHub Pages: Settings → Pages → Deploy from a branch → main → /(root). این تنظیم فقط یک‌بار لازم است. پروژه در مرورگر هم می‌تواند بدون انتشار باز شود.
