# استاندارد دادهٔ پلن روزانه (Daily Plan Schema)

این سند قرارداد دادهٔ پروژه است. سایت بدون کتابخانهٔ خارجی، فایل `data/plans.js` را می‌خواند. تاریخ باید `YYYY-MM-DD` باشد؛ زمان رویدادها با ساعت محلی `Asia/Baku` ثبت شود. تمام اعداد قیمت باید متن باشند تا صفرهای انتهایی یا فرمت مخصوص نماد ناخواسته تغییر نکند.

## قالب کامل قابل کپی

## تعریف فیلدها و قواعد

- `date`: تاریخ روزی که پلن برای آن تهیه شده است؛ برای پلن فردا، تاریخ فردا را وارد کن.
- `status`: تا پایان بازبینی `draft` بماند. فقط وقتی تمام کنترل‌ها انجام شد، `ready` کن.
- `bias`: جهت غالب بازار، نه فرمان خرید/فروش. مقدار `conditional` برای زمانی است که جهت به شرط وابسته است.
- `quality`: کیفی و توضیح‌پذیر؛ درصدهای احتمال بدون روش آماری معتبر درج نکن.
- `referencePrice`: همراه با منبع و زمان ثبت باشد؛ قیمت مرجع، قیمت زندهٔ تضمین‌شده نیست.
- `levels`: قیمت، تایم‌فریم، اهمیت و منطق واکنش باید کنار هم ثبت شوند؛ سطوح بدون دلیل اضافه نشوند.
- `scenarios`: هر سناریو حتماً trigger و invalidation داشته باشد. هدف قیمت بدون شرط ورود، پیشنهاد اجرایی کامل نیست.
- `events`: خبر مهم و زمان آن را از تقویم معتبر بررسی کن؛ ارقام قبلی/پیش‌بینی را حدس نزن.
- `risk`: اگر ارزش پیپ، اندازهٔ قرارداد، ارز حساب یا هزینه نامعلوم است، اندازهٔ پوزیشن را قطعی اعلام نکن.
- `sources`: آدرس و زمان بررسی منبع را ثبت کن تا معلوم باشد تحلیل بر چه اطلاعاتی تکیه دارد.

## اعتبارسنجی پیش از انتشار

1. تاریخ و منطقهٔ زمانی درست باشند.
2. قیمت‌ها و رویدادها منبع و زمان بررسی داشته باشند.
3. سناریوها با هم تناقض حل‌نشده نداشته باشند؛ اگر دارند، شرط تفکیک‌شان توضیح داده شود.
4. هیچ سناریویی بدون trigger و invalidation نباشد.
5. اسپرد، کمیسیون، لغزش، اندازهٔ پوزیشن و حد زیان روزانه نادیده گرفته نشوند.
6. هیچ‌گاه برای پر کردن قالب، دادهٔ ناموجود را حدس نزن؛ «نامشخص / تأیید نشده» بنویس.
